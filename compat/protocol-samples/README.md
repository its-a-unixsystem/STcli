# Canonical protocol samples

These samples let frontend implementations parse every public CLI protocol kind without running STcli.

| Sample | Public schema | In-band identifier |
| --- | --- | --- |
| `envelope-success.json` | `schemas/cli-envelope.schema.json` | `stcli.cli/v1` |
| `envelope-error.json` | `schemas/cli-envelope.schema.json` | `stcli.cli/v1` |
| `turn-stream.jsonl` provider-event lines | `schemas/cli-event.schema.json` | `stcli.cli-event/v1` |
| `turn-stream.jsonl` final line | `schemas/cli-envelope.schema.json` | `stcli.cli/v1` |
| `turn-capsule-portable.json` | `schemas/turn-capsule.schema.json` | `stcli_turn_capsule` version `1.0` |
| `turn-capsule-thin.json` | `schemas/turn-capsule.schema.json` | `stcli_turn_capsule` version `1.0` |

The integration test runs the real binary against the shipped provider-test process. It converts each JSON payload to canonical JSON and replaces only run-specific entity IDs, hashes, RNG seeds, provider addresses, and test certificates with stable schema-valid values. Keys, containers, event ordering, and other payload values come from the binary. The checked-in bytes include a trailing newline.

## Regeneration

Normal test runs only compare generated bytes with the checked-in files. Updating them requires this explicit opt-in:

```bash
STCLI_REGENERATE_PROTOCOL_SAMPLES=1 cargo test -p stcli-cli --test protocol_samples
cargo test -p stcli-cli --test protocol_samples
```

Review every diff under `compat/protocol-samples/`; do not treat regeneration as an approval step. If a payload shape changed, review and version the affected public contract in `schemas/` and its in-band identifier (`schema` for CLI payloads or `format`/`version` for Turn Capsules) in the same change. The schema-identifier guards in `protocol_contracts.rs` must be updated deliberately when that contract changes.
